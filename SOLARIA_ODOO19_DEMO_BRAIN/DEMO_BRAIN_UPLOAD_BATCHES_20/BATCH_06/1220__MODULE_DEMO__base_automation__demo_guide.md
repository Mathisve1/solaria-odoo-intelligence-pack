# Module Demo Pack: Automation Rules (`base_automation`)

| Attribute | Value |
|---|---|
| Edition | Community |
| Category | MODULE_DEMO (demo guidance only; product truth lives in the Intelligence Pack module docs, routed via foundation 0012) |
| Rule | Every claim keeps its edition tag and claim label (foundation 0018); nothing here is demo-ready until rehearsed (foundation 0017) |

## Demo purpose
Process glue without code, on any edition: the two-minute rule that removes a daily chase.

## Best personas
COO, operations managers, admins, CIO (governance)

## Prerequisites
- A scenario from the client's chase-list (stale lead, idle ticket, missing data)
- admin access to build live

## Minimum demo data
- Records that will trigger the rule
- a colleague user to receive the activity/notification

## Recommended flow
- Name the chase
- build the rule live (trigger, condition, action)
- make a record qualify
- watch the activity/notification land

## Wow moments
- Built in two minutes, live
- 'this is Community' (corrects the Enterprise misconception)
- the rules list as a governance registry

## Common mistakes
- Hard-blocking promises (advisory vs blocking honesty)
- rule spaghetti as a workflow engine
- forgetting ownership/monitoring

## Standard vs custom notes
- Rules ARE rung 4
- code-type actions drift to rung 5 governance
- complex event logic: custom, honest

## Community vs Enterprise notes
Community, importantly; AI steps in automations are the Enterprise extension, labelled

## Likely objections
- Who maintains rules (owner and registry answer)
- can it block saves (prefer native constraints, honest)

## Validation checklist
- Trigger list vs their cases live
- governance owner named
- monitoring in the run book

## Backup flow
Identical rule pre-built and disabled: enable it if live building stumbles
