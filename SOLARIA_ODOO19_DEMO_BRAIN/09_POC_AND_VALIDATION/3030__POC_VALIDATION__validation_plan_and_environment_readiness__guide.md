# Validation Plan and Environment Readiness

Category: POC_VALIDATION.

## The validation plan (per pursuit)
For every open claim (validation register): the route, the effort class, the sequencing.
- Live-check items: batched into rehearsal sessions (0017) or POC criteria (3010).
- Commercial items: routed to the commercial desk with dates; never resolved by the demo team.
- Localisation items: routed to country experts with the statutory-output samples from intake 0270.
Sequencing rule: validate cheapest-first when it can kill the deal honestly (a missing country capability found early saves everyone months), highest-impact-first otherwise.

## Demo environment readiness checklist
- [ ] Edition matches the conversation and is verified (0011)
- [ ] Version 19.0 noted; apps = storyline scope only (0016)
- [ ] Demo data checklist green with owners (0016)
- [ ] Reset procedure executed once successfully
- [ ] Backup records staged; recording of rehearsal exists
- [ ] Access: presenter logins per persona work; passwords ready; no admin-only demos
- [ ] Network plan (venue wifi tested or hotspot fallback)

## POC environment readiness (adds to the above)
- [ ] Client-data handling rules implemented BEFORE data arrives (3040)
- [ ] Access limited to named POC participants; client access defined
- [ ] Logging of what was configured (the POC configuration becomes evidence and later reusable design)
- [ ] Teardown/retention date agreed in writing
