## Demo purpose
Work delivered visibly: tasks with stages, customer collaboration, and the sold-to-billed chain for services.

## Best personas
Project managers, services director, CFO (margin)

## Prerequisites
- Project template with their phases
- sale_project bridge if billing shown
- analytic setup for margin

## Minimum demo data
- Flagship project with tasks across stages
- timesheets logged
- one milestone ready to invoice
- portal customer user

## Recommended flow
- Service quote confirms
- project and tasks appear
- work logged from the task
- milestone reached, invoice created
- margin view

## Wow moments
- Quote line becoming a project automatically
- the live margin per project view
- customer portal comment beat

## Common mistakes
- Task-management-tool framing (it is the billing chain that differentiates)
- stage-mess from unplanned demo data

## Standard vs custom notes
- Stages, templates, milestones: configuration
- Gantt and forecasting: Enterprise, labelled
- portfolio governance: design work, honest

## Community vs Enterprise notes
Core Community; Gantt/map views, planning/forecast, timesheet validation are Enterprise

## Likely objections
- We use Jira (boundary/coexistence honesty)
- margin accuracy (timesheet adoption named as the real driver)

## Validation checklist
- Billing models reproduced per contract type
- analytic design with finance
- portal visibility choices

## Backup flow
Milestone invoice pre-created in draft; second project staged
