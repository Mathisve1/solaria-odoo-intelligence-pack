## Priorities
- Architecture simplification
- Security and access governance
- Maintainable customisation, upgrade path, vendor risk

## Likely frustrations
- Integration sprawl between best-of-breed tools
- Undocumented customisations in the legacy ERP
- Being blamed for business tools IT never chose

## Business KPIs
Number of systems and interfaces, incident volume, upgrade cost, security posture, IT run cost

## Demo emphasis
- One data model story: the same record travelling, no interfaces
- Roles and access shown live (login as different personas)
- Governance artifacts: customisation registry, staging flow, upgrade policy

## Relevant Odoo modules
base/platform story, security groups shown live, web_studio with governance framing (Enterprise), base_automation (Community), integration boundaries named honestly

## Suitable Challenger insights
- The integration tax of best-of-breed is permanent; every interface is a small project forever
- Governed no-code beats ungoverned custom: the risk is not customisation, it is unregistered customisation

## Likely objections
- Open source security and support?
- Lock-in to one partner?
- How do upgrades really work with customisations?

## Unsuitable demo content
- Business fluff without architecture substance
- Hand-waving over integration boundaries

## Opening questions
- How many systems and interfaces run your core processes today?
- What did your last ERP upgrade cost, and why?

## Recommended closing
We propose a technical annex session: your architects, our architects, the data model, the security model and the upgrade policy on the table.
