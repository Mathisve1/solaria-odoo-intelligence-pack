# Audience and Persona Adaptation

| Attribute | Value |
|---|---|
| Foundation file | 0008 of 20 |
| Purpose | The same demo content lands differently per person. This file fixes the permanent adaptation logic; the persona packs (0400 range) add depth per role. |

## 1. The adaptation rule
Every key attendee gets: an intended takeaway, a tailored wow moment, language at their altitude, and a prepared response to their likely objection. If two attendees need incompatible demos (CEO and warehouse operator), split the session into explicitly labelled chapters rather than averaging into mush; averaging convinces no one.

## 3. KPI language per altitude
Executives: cycle time, margin, close days, win rate, working capital. Managers: backlog, first-time-right, utilisation, SLA hit rate. Users: clicks, minutes, "no more re-typing". Use the client's own KPI names from intake wherever available.

## 4. Likely-objection sourcing
Each persona's default objection (persona packs) is merged with intake D ("likely objection" per attendee); the top five go to the objection sheet (file 0015 framework). The decision maker's objection always makes the top five.

## 5. Language rules
Demo language follows intake C. Avoid Odoo jargon with non-IT audiences (say "quotation approval", not "sale order state"). Never say "standard Odoo" to a client without the edition tag resolved internally first; the room only hears claims that carry the right labels.
