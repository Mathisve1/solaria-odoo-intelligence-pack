# Demo Storyline: Project-to-Invoice (services)

| Attribute | Value |
|---|---|
| Category | STORYLINE (instantiates the 12-beat framework, foundation 0009) |
| Rules | Timing limits per format apply (0014); every beat needs data (0016) and rehearsal (0017); editions and claim labels always (0011, 0018) |

## Client problem
Sold days leak between delivery and billing; margin is a year-end surprise.

## Audience
Services director, project managers, CFO; 45 to 60 minutes

## Prerequisites
- sale_project + hr_timesheet rehearsed
- flagship project staged
- rates configured

## Modules (edition)
- project (C)
- hr_timesheet (C)
- sale (C)
- timesheet grid/validation and planning labelled (E)

## Start state
Signed service quote for a phased engagement

## End state
Milestone invoiced; margin per project on screen

## Step-by-step demo flow
1. Quote confirms, project and tasks appear
2. consultant logs time from the task in seconds
3. (E, labelled) manager validates the week in the grid
4. milestone reached, invoice created from delivered value
5. the margin view per project
6. unbilled-hours flush beat

## Wow moments
- Quote-to-project automation
- the two-minute timesheet reality
- live margin per project

## Challenger insight
Unbilled hours are a friction problem, not a discipline problem: capture at the task beats reconstruction on Friday.

## Likely questions
- Our billing models?
- utilisation views?
- Jira coexistence?

## Risks
Rate/margin data unprepared makes the payoff beat empty

## Validation points
- Billing models per contract type
- analytic design
- adoption plan for capture

Task time-log to milestone invoice

## Executive version (30 min)
Leakage framing, compressed chain, margin-visibility close
