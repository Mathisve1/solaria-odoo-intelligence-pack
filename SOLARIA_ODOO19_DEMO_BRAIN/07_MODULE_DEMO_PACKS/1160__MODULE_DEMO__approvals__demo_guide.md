# Module Demo Pack: Approvals (`approvals`)

| Attribute | Value |
|---|---|
| Edition | Enterprise |
| Category | MODULE_DEMO (demo guidance only; product truth lives in the Intelligence Pack module docs, routed via foundation 0012) |
| Rule | Every claim keeps its edition tag and claim label (foundation 0018); nothing here is demo-ready until rehearsed (foundation 0017) |

## Demo purpose
The end of email approvals: requests with visible approver states, policy as configuration.

## Best personas
CFO, COO, process owners, admins

## Prerequisites
- Enterprise database
- 2-3 categories configured (spend, travel, contract) with approver sets

## Minimum demo data
- Requests in various states
- one request staged for live approval by a second user

## Recommended flow
- Employee picks the tile
- fills the category-defined form
- submits
- approver acts from activity
- trail visible
- purchase bridge if relevant

## Wow moments
- Two-browser moment: submit here, approve there, trail updates
- changing the policy by editing the category (no code)

## Common mistakes
- Overpromising conditional matrices (validate expressiveness per matrix line)
- duplicating native app approvals (expenses, time off)

## Standard vs custom notes
- Categories, approver sets, minimums: configuration
- DoA-grade engines with delegation calendars: custom/design, honest

## Community vs Enterprise notes
Enterprise-only; also mention Studio approval rules for button-level gates (Enterprise) when relevant

## Likely objections
- Our matrix is complex (line-by-line mapping exercise offered)
- delegation/out-of-office (validate live)

## Validation checklist
- Matrix mapped to categories with a live test
- overlap with native app approvals resolved
- delegation behaviour checked

## Backup flow
Approved twin request ready to show the after-state
